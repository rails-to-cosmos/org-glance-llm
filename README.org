#+TITLE: org-glance-llm

LLM sessions for [[https://github.com/rails-to-cosmos/org-glance][org-glance]] headlines — a separately installed *plugin*.

Every headline gets its own [[https://github.com/rails-to-cosmos/agnostic-llm][agnostic-llm]] session, rooted in that headline's
own directory, so the CLI's per-directory context accumulates per note.  Claude
Code and OpenAI Codex are supported as separate providers.

* Install

#+begin_src emacs-lisp
(add-to-list 'package-archives
             '("rails-to-cosmos" . "https://rails-to-cosmos.github.io/elpa/"))

(use-package org-glance-llm
  :after org-glance
  :ensure t
  :init (setq org-glance-plugins '(llm)))
#+end_src

=org-glance-plugins= is core's plugin list: listing =llm= makes
=org-glance-init= load this package.  =I= in =org-glance-transient= does the
same interactively (and remembers it).  The dependency runs one way — this
package requires org-glance — so a plain org-glance install stays free of
=vterm=.

* Use

| Key       | Where             | Action                                                   |
|-----------+-------------------+----------------------------------------------------------|
| =P=       | transient         | choose the provider                                      |
| =l=       | transient         | pick a headline, open its session                        |
| =L=       | transient         | table of every session: running / exited / stopped       |
| =C-c l=   | material buffer   | open THIS headline's session                             |

A session is identified by its *directory*: the headline's
content-addressable data dir, or its =:ORG_GLANCE_PROJECT_DIR:= drawer
property when set (=C-c d= in a materialized buffer sets it).  Reopening a
headline switches to the live buffer for the selected provider, so one headline
may keep an independent Claude session and Codex session;
the =*llm:TITLE*= buffer name is cosmetic, so two same-titled headlines
never share one.

** Provider and model

The transient's =P= chooses and saves the provider before a session is opened.
The pinned =agnostic-llm= menu owns model selection and also exposes the same
provider command:

| Key | Action                                                           |
|-----+------------------------------------------------------------------|
| =B= | choose and save the provider (=claude=, =codex=, or a registered one) |
| =-m= | choose a model from the selected provider's catalog               |
| =M= | save a default model for that provider                              |

Changing provider immediately changes the models offered by =-m=.  The plugin
does not maintain a second model list.  Claude sessions use the Claude CLI and
session store; Codex sessions use the Codex CLI and its date-partitioned rollout
store.  Install and authenticate the CLI for each provider you use.

** The sessions table (=L=)

One row per session, with its state derived live:

| State     | Meaning                                                  |
|-----------+----------------------------------------------------------|
| =running= | live buffer, live process                                |
| =exited=  | live buffer, process gone                                |
| =stopped= | no buffer, but the provider recorded a transcript        |

=RET= pops to a running session or restarts a stopped one with the currently
selected provider, =m=
materializes the owning headline, =k= kills a live buffer, =g= rescans.

=L= reads only the selected provider's recorded sessions and overlays its live
buffers.  Claude's directory-encoded store and Codex's rollout metadata both map
directly back to headline ids, so opening the table remains O(recorded sessions)
and never scans every headline.

* Development

#+begin_src sh
make init   # install deps (incl. org-glance + agnostic-llm), compile, install
make test   # ert suite
make lint   # checkdoc + relint
#+end_src

The suite stubs =agnostic-llm= entirely (its =vterm= dependency cannot load
in batch), so it exercises this package's own logic — session-dir
resolution, the state machine, the cache round-trip, the table wiring —
against a real org-glance store.

* Plugin contract

This package is the reference implementation of org-glance's plugin
interface (see =docs/proposals/2026-07-23-plugin-interface.done.org= there):

- provides feature =org-glance-llm=, loaded error-demoted from
  =org-glance-plugins=;
- self-registers its transient row (remove-then-append, so reloading never
  duplicates) and its own =C-c l= material-buffer key;
- persists only derived state, through core's public sidecar API
  (=org-glance-graph:cache-read= / =:cache-write=);
- uses core's public =:= API only — no =--= internals.
